# skala-vue

##### 날씨 확인 웹페이지

##### 10반 심준용

<br />

\- 컴포넌트가 한 가지 역할만 하고 있나요

4가지의 컴포넌트로 나누기는 했지만 조금은 대칭이 맞지 않는 부분이 있어 차후 수정이 필요할 수 있습니다.

\
\- 굳이 반응형으로 안 만들어도 되 싸지 않았나요? (반응형 남용)

일부 남용한 것이 있어 차후 개선이 필요합니다.

\
\- API 요청 중·실패 상황을 사용자가 알 수 있게 처리했나요? (로딩·에러 처리)

요청 중이나 실패중일 때 로딩 혹은 에러 페이지를 만들어 사용자가 어떤 상황에 놓여있는지 파악하기 쉽게 처리해 놓았습니다.

\
\- 변수·함수 이름만 보고 무엇을 하기 (가독성)\
가독성은 꽤나 좋은 편이었습니다. AI에게 어느정도 맡겨놓았더니 깔끔하게 정리해주었습니다.

1. 추가 기능

* 사용자가 검색을 하여 화면에 나타나 있지 않은 도시 추가 가능

* 일부 주요도시는 한국어로도 검색 및 추가 가능

* 검색 실패시 모달을 통해 에러메시지 제공

* 필요 없는 도시는 삭제 가능

* 온도 상태에 따른 상태변화 '추움'추가 및 각 상태별 색깔 삽입

* 각 도시별 상세 페이지 이동해 습도, 바람 등 확인 가능

* 도시의 시간과 날씨별 이미지 삽입

* 기타 등등

3. **4일간 어려웠던 점과 해결 과정**

&#x20;사실 어렵지 않았던 적이 없었던 것 같습니다. SKALA에 입과하기 전에 HTML조차 만져본 적이 없을 정도였습니다. 새로운 지식과 기술을 배우다보니 꽤나 많이 따라가는게 꽤나 어려웠던 것 같습니다. 특히나 Router, View, Store 등을 사용할 때에는 파일이 여러 갈래로 나뉘어 더 정신이 없었던 것 같습니다.

&#x20;그래도 AI를 사용해서 하나씩 기능들을 추가하기도 하고 뒤에 발생하는 문제들을 해결하는 것은 마치 게임 퀘스트를 하나씩 완수하는 느낌이었습니다. 하지만 AI와 저 혼자만의 힘으로는 해결되지 않는 것은 분명히 있었습니다. 그럴 때는 옆에 있는 동료에게 물어보거나 매니저님과 실습교수님의 도움을 받으면서 막혀있던 부분을 시원하게 해갈하였습니다.

이번 웹사이트를 만들면서 비록 부족하지만 나만의 개인 프로젝트를 진행하는 느낌이었고 짧지만 많은 경험을 통해 많은 것을 배웠습니다. AI를 활용할 때 더 디테일하고 더 집요하게 사용하는 방식을 체화하게 되었고, 개인의 프로젝트이지만 동료분의 도움을 받는 것은 프로젝트의 개선에 지대한 영향을 미친다는 것을 체득했습니다.
